# 商品定向研究

## 研究目标

不是写品牌百科，而是回答：

> 这个具体商品为什么可能在中国被购买，应该卖给谁，与什么比较，以什么价格和叙事进入市场？

## 输入与新品边界

最低输入：品牌、准确 SKU 和目标市场。标签、进口、成本、库存、履约与平台信息可以后补；用户未指定成交平台时，直接按通用电商任务研究。

用户明确指定平台或要求平台可上架版本时，再读取 `platform-overlays.md` 并收集会实质改变策略的附加信息。平台信息不得成为商品研究、目标顾客推测和商详主体产出的前置门槛。

默认这是尚未上架的新品：

- 不搜索目标店铺页面来定义商品角色；
- 不假设已有自有销量、评论、复购或广告数据；
- 相邻规格、同系列与竞品评论可用于建立方向性假设，但不能冒充目标 SKU 评价。

只有用户明确说「优化现有商品页」时，才审计目标页面与自有数据。

## 资料审计

先盘点用户给出的报告、网页、标签、产品图、价格、成本和体验反馈。按下面六路标记「已有／需补／暂缺」：

| 研究路由 | 必须回答的问题 |
|---|---|
| 商品与品类 | 规格、原料或材质、工艺、用途、限制、选购标准、常见误区是什么？ |
| 顾客与评论 | 使用场景、满意点、抱怨、异议、欲望、复购语言和原话是什么？ |
| 竞品与替代 | 顾客还会买什么，各自主张、机制、证明、价格和页面结构是什么？ |
| 品牌与故事 | 哪些产地、历史、人物、工艺或文化线索能解释差异并支撑信任？ |
| 中国交易 | 已有人民币价格、进口模式、销售单元、包邮、破损、退换与渠道风险是什么？ |
| 合规与标签 | 中文标签、成分或材质、过敏原、保存、认证和禁止宣称是什么？ |

已有长报告时，只补会改变商品、人群、卖点、价格或文案的缺口；不要重跑无关的完整深度研究。

## 搜索方法

每一路先定来源，再定查询：

1. 官方商品页、品牌页、标签、行业协会、监管或标准；
2. 零售商页面、专业媒体、料理或使用指南、访谈和报道；
3. 电商评论、论坛、社媒帖子、视频文字和问答；
4. 反向词：`complaint`、`problem`、`review`、`alternative`、`vs`、`价格`、`不好用`、`怎么用`。

同一个关键问题至少查一个事实源和一个市场／用户源。官方回答「是什么」，评论和市场页面回答「顾客为什么在意」。来源层级不等于营销价值高低：一条可信报道或真实社媒语言可以成为好钩子，只要不把它夸大成统计结论。

## 评论抓取与整理

优先抓取目标 SKU；不足时依次扩展到同品牌同产品线、直接品类竞品、相邻替代品。每条记录：

```text
review_id｜平台｜URL｜访问时间｜商品与 SKU｜评分｜日期
原文｜中文整理｜已购或激励状态（如可见）｜主题｜截图路径
```

必须同时保留：

- 原始页面截图或完整上下文，供后续营销素材筛选；
- 结构化文字，供痛点、欲望和顾客语言分析；
- 评价对象边界，避免把 500ml 评论写成 360ml 评论。

评论分析不止列正负面。先统计主题，再为每个主题追问：

```text
表面上在说什么？
→ 背后的购买任务或担心是什么？
→ 现有替代办法为什么不够好？
→ 商品可以提出什么新解释或结果？
```

少于 10 条时不做百分比推断，但仍可用于发现语言、场景和异议。

## 研究成熟度

| 层级 | 已有资料 | 可完成的判断 |
|---|---|---|
| L1 | 商品与公开品牌事实 | 商品事实、初步差异与证据缺口 |
| L2 | 加入竞品、价格与跨渠道评论 | 痛点、顾客假设、市场空位与方向性定价 |
| L3 | 加入自家试吃、客户或首批买家反馈 | 校准核心卖点、用途与商品架构 |
| L4 | 加入成本、流量、成交、退货与复购 | 价格底线、利润和迭代决策 |

输入只有 L1／L2 时仍须形成明确销售假设，并写出上市后如何验证；不得用「资料不足」代替决策。

## 内部研究输出

`internal/research-audit.md` 至少包含：

1. 商品事实台账与限制；
2. 竞品／替代品对照矩阵；
3. 评论主题频次、原话与背后购买心理；
4. 品牌故事与可视化资产；
5. 人民币价格锚点；
6. 关键缺口与补证计划；
7. 来源 URL、访问日期与截图索引。
