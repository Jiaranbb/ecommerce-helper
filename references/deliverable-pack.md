## 交付原则

「电商素材包」是本 Skill 的完整主交付，不是把若干文件临时装进一个文件夹。

- 商品销售战略报告是判断母稿；PDF 是它的分享阅读版，不另写第二套内容。
- 商详方案是成交路径；保留多方案和最终定稿，只输出 Markdown。
- 商详图片是最终商详文字的视觉实现。
- 社媒素材是从同一战略母稿派生的渠道化表达，不得改写产品事实和价格条件。
- `internal/` 保存给下游 Agent 使用的结构化中间件，不对客户报告暴露方法来源。

## 战略报告 PDF

完成 `商品销售战略报告.md` 后，先读取 [pdf-style.md](pdf-style.md)，再使用 `scripts/md_to_pdf.py` 导出同目录 PDF：

```bash
python3 scripts/md_to_pdf.py \
  "01-商品销售战略/商品销售战略报告.md" \
  "01-商品销售战略/商品销售战略报告.pdf" \
  --date YYYY-MM-DD
```

要求：

- PDF 面向品牌方、渠道方或合作伙伴阅读，隐藏 YAML frontmatter、内部路径和方法来源；
- 使用「封面 → 阅读导航 → 结论摘要 → 分页章节 → 最终决策卡 → 主要来源」的报告级结构；
- 保留标题层级、表格、列表、引用和链接；传播钩子中的引用标题不得误判为章节；
- A4 竖版、暖白底、砖红层级、横线表格，正文适合屏幕和打印阅读；
- 来源附录使用中性低强调层级，每条网络来源同时显示来源名称、完整 URL 和可点击链接；
- 末尾固定保留 eCommerce-helper 的 Skill 作者署名，其中包括设计与维护者「嘉然 Jiaran」、公开交流微信 `evadebot` 与个人网站 `https://c.aoao.ai`；用户指定封面报告署名时另传 `--author`，不得混淆两种身份；
- Markdown 更新后必须重新导出 PDF，避免双版本内容漂移；
- 导出后用 `pdfinfo` 检查页数，用 `pdftoppm` 渲染全部页面为 PNG；逐页检查中文、表格、分页、页码、链接文字、孤行和溢出；
- 再用 `pypdf` 或 `pdfplumber` 抽取文本，抽查标题、人民币价格、SKU 和关键结论是否存在。

渲染器默认优先使用 Chrome，再回退到 WeasyPrint；Chrome 路径可通过 `--chrome` 或 `ECOMMERCE_HELPER_CHROME` 指定。不要以未经目视检查的系统打印 PDF 作为最终交付。

## 素材清单

`00-电商素材包清单.md` 至少包含：

```markdown
# [品牌／商品] 电商素材包清单

> 版本日期：
> 主推 SKU：
> 核心主张：
> 建议零售价：
> 本包适用渠道：

## 一、快速使用
[先看什么、直接可用什么、哪些地方需要替换]

## 二、交付文件
| 模块 | 文件／目录 | 状态 | 用途 | 使用前注意 |
|---|---|---|---|---|

## 三、发布建议
[推荐发布顺序、素材复用关系、首轮测试]

## 四、变量与占位符
[日期、活动权益、购买链接、库存、客服二维码等]

## 五、待客户补充／待验证
[尚无事实、素材或授权支持的项目]
```

不要在清单中使用内部方法名。清单的任务是让接手者五分钟内知道有哪些文件、先用什么、哪些不能直接发。

## 部分交付

用户只要求战略、商详、图片或社媒其中一部分时：

- 只生成该阶段必要文件，不制造空壳；
- 仍使用一致的编号和命名，便于未来追加；
- 在总清单或当前阶段说明中标记范围；
- 若只做社媒素材，先建立最小 `internal/messaging-matrix.md`，避免无战略依据地批量写稿。

## 最终验收

- 目录编号、文件名和清单完全对应；
- Markdown 与 PDF 版本、日期和内容一致；
- 商详文字与商详图片逐页对应；
- 社媒文案与配图按角度或编号对应；
- 所有对外材料中的品牌名、SKU、规格、价格、活动、CTA 和链接一致；
- 未经确认的促销条件、用户评价、功效和机构背书没有被写成事实；
- 所有占位符集中列出，没有散落的 `TBD`、示例链接或假二维码；
- 对外文件不含内部推理、方法来源、Agent 指令或本地绝对路径。
