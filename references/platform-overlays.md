# 平台增量（Platform Overlay）

## 基本原则

eCommerce-helper 的商品研究、目标顾客、痛点、竞品、卖点、价格、商详与分屏商品图是一套通用底座。平台适配是在这套底座上增加信息和输出差异，不是先选平台才能开始，也不是为每个平台重做一套商品战略。

用户未指定平台时，不询问平台，直接执行通用流程。用户明确指定平台，或要求产出可以直接用于某平台上架时，才使用本文件。

## 先确认的平台信息

先区分：

```text
主要成交平台：最终在哪里下单？
流量来源：顾客从哪里看到并进入商品？
任务类型：新品创建／已有链接优化？
本轮目标：通用商详／平台可上架版本／多平台分发？
```

不要重复询问用户已经给出的信息。缺失字段集中问一次；不影响通用判断的字段可以后补。

## 常见平台附加输入

| 平台 | 需要补充的信息 | 主要增加的输出 |
|---|---|---|
| 淘宝／天猫（Taobao / Tmall） | 店铺类型、类目、既有标题与关键词、活动与服务承诺、现有链接数据 | 货架标题与关键词、属性字段、活动表达、搜索与推荐入口差异 |
| 京东（JD） | 自营／POP、类目参数模板、仓配方式、服务与时效承诺 | 参数组织、履约信任、服务表达、货架标题与促销差异 |
| 拼多多（Pinduoduo） | 目标价格带、成本底线、SKU 拼法、运费地区、活动或补贴条件 | 价格梯度、规格命名、拼单／活动表达、低门槛成交设计 |
| 小红书店铺（Xiaohongshu Shop） | 店铺成交或外链承接、内容账号、笔记／直播／店铺入口、现有种草素材 | 种草钩子、笔记到商品卡承接、站内搜索词、内容与成交的一致性 |
| 抖音电商（Douyin Commerce） | 短视频／直播／商城入口、达人或自播、佣金、直播权益、库存与履约 | 短视频／直播话术、商品卡信息、即时权益、内容节奏与货架承接 |
| 多平台（Omnichannel） | 主成交平台、各平台角色、是否统一价格、库存与活动冲突 | 一份共用商品战略，加各平台入口、权益和字段差异表 |

平台规则、字段和活动机制可能变化。用户要求「可直接上架」时，核查该平台当前官方规则；仅做策略和文案时，不为罗列规则打断商品推演。

## 产出叠加方式

通用报告和商详保持完整，只在必要位置追加「平台增量」：

1. 商品销售战略报告：增加平台购买环境、流量承接、价格或履约约束；
2. 商详文字：增加该平台需要的标题、搜索词、商品卡、直播／种草话术或属性字段；
3. Offer：增加平台活动、券、佣金、包邮或服务条件，但不得虚构；
4. 上线验证：增加该平台能取得的曝光、点击、加购、成交和退款指标；
5. 分屏商品图：继续使用通用 3:4、1080 × 1440 的独立页面，不按平台另造一套主体图；
6. 社媒素材：只有用户指定发布渠道或要求直接发布时，才核查当前字数、图片比例、标题、链接和商业内容标识等平台规则；不因平台差异改变战略母稿。

如果用户另行要求首图、搜索缩略图、直播卡片或广告素材，把它们作为通用分屏图之外的衍生资产单独处理，不改变商详主体图规格。
